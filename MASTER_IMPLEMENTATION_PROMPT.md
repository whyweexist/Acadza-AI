# Master implementation brief — SQLite edition

You are a senior full-stack engineer, AI orchestration architect, security engineer and faculty-product designer. Build a student-report-to-safe-fix system for Acadza's ~800,000 question bank using the supplied production-format `questions.json`, `reports.json` and `taxonomy.json`, with **SQLite only**. Implement rather than merely describe it. The assignment README is authoritative.

**Domain rules:** `question._id` is the canonical key; `qid` is not unique. The body is `question[question.questionType]` where `questionType` is `scq`, `mcq`, `integerQuestion`. Group by question and retain every report ID. `TriageResult` is a Pydantic discriminated union by `verdict`: defects require taxonomy repair and may have an edit; all other verdicts have repair/edit null and `no_change` route. Export only the primary `{field,find,replace}` surgical edit, allowing a list internally. Store the triage snapshot's SHA-256 hash per case. Unreported defect signals go in `findings.json`, never `results.json`.

**Pipeline:** ingestion and normalization → static signals (option count, blank/duplicate options, MCQ list shape, raw LaTeX, exam tags, figure reference without `quesImages`, newer `errorHistory` entries, noise, stray MathML ampersand) → async concurrent tracks under a semaphore: `claim` sees untrusted JSON comments; two independent solvers see only stem/options (not key, solution or reports), `solution_audit` sees question/solution without key, `text_lint` and `metadata` independently check content → strong adjudicator picks taxonomy labels, exact patches and evidence → deterministic safety gate → auto-eligible/faculty-review/no-change → report-specific empathetic reply and audit metadata. Pydantic-validate every expert JSON; retry once then quarantine to human review without inventing defect evidence.

**Safety policy:** edit field in `taxonomy.repairs[repair].fields`, `auto:false` never auto-writes, exact unique find, nontrivial replacement, patched copy must remain consistent. Spelling no digit/symbol/MathML changes; noise/exam tags deletion only; answer form additive; option repair raw stem unchanged and unique options; stem data numbers supported in original solution; answer key must be proven by two agreeing independent solvers and valid answer shape, with solution-audit reconciliation; solution repairs must end at keyed answer. A student's comment is never an instruction or source of executable edit text. Block stale question hashes. Score confidence from evidence agreement, not self-reported model probability. Require >=0.85 for auto-eligible and >=0.90 for answer keys. Failed checks go to review.

**SQLite architecture:** Python FastAPI + Pydantic + httpx + aiosqlite; SQLite WAL, short transactional writes, foreign keys, indexed report aggregation, versioned source snapshots, case revision checks, durable audit events and idempotency keys. No PostgreSQL, Redis or distributed worker infrastructure. Single persistent SQLite writer only. A recorded approval is not a production mutation.

**Interactive faculty UI:** Next.js + TypeScript. Fast question-level priority queue, real responsive UI, search, filters, sorting, quick keyboard navigation, native MathML, show/hide original solution, AI evidence, explanation of confidence, exact before/after field diff, edited rendered question preview, all original reports, per-report reply preview, approve/edit/reject modal, audit trail, dark mode, offline read-only demo. Use modular components rather than a giant placeholder dashboard. Safely sanitize untrusted HTML before display. Server-only review credentials.

**Required deliverables:** reproducible repository, complete `results.json`, `PROMPTS.md` with prompts verbatim and honest revisions/mistakes, one-page `PRODUCT.md`, README, source data, findings, tests (run only if user authorizes), deployment plan, walkthrough script. Never invent tests, hidden-ground-truth accuracy, real LLM output or live deployment links. Safety, student impact and faculty UX outrank infrastructure theatrics.
